Project Type

Full-stack web application for managing factory inventory across multiple global warehouses. Features real-time visibility into stock levels, orders, demand forecasts, and financial metrics with multi-language support.

Key Characteristics

  • 3 Warehouses: San Francisco, London, Tokyo
  • 32 Inventory Items across 5 product categories
  • 4 Global Filters: Time Period, Warehouse, Category, Order Status
  • Multi-language Support: English & Japanese with persistent locale
  • In-Memory Data: No database, JSON-based mock data
  • Real-time Filtering: Query parameters propagate through full stack

Frontend Data Flow

  • useFilters.js - Global singleton maintaining filter state (period, warehouse, category, status)
  • Vue Components - Watch filter changes, call api.js methods
  • api.js - Builds query parameters from filters, sends GET request
  • Axios - Handles HTTP, returns promise with JSON data
  • Computed Properties - Transform raw data for display (currency formatting, aggregations)
  • useI18n.js - Translates strings and formats currency (USD/JPY)

Backend Data Flow

  • FastAPI Router - Receives request with query parameters
  • Filter Parser - Extracts warehouse, category, status, month from query
  • apply_filters() - Chains filter functions to narrow results
  • filter_by_month() - Matches ISO dates or quarter notation (Q1-2025)
  • In-Memory Data - Filtered list created from pre-loaded JSON
  • Pydantic Models - Validates and serializes to JSON response
  • CORS Headers - Enabled for localhost:3000

💡 Technical Decisions

Architecture Choices

  • In-Memory vs. Database - JSON files loaded at startup keep development simple, fast iteration, no DB setup
  • Single-Page Application - Vue router eliminates page reloads, provides smooth UX for data filtering
  • Query Parameters for Filters - Allows bookmarkable filter states, shareable URLs, sync across tabs
  • Pydantic Models - Automatic validation, serialization, and OpenAPI documentation
  • Composables for Shared Logic - Reactive state management without Redux/Vuex overhead

Design Patterns

  • Filter Singleton - useFilters.js as single source of truth for filter state across all views
  • Computed Properties - Transform raw API data for display (aggregations, formatting)
  • Modal Pattern - Detail views as overlays rather than separate pages
  • Promise-Based API Client - Axios handles async requests, components await responses

Performance Considerations

  • Frontend - All 32 inventory items fit in memory, no pagination needed
  • Backend - Filtering happens in-memory (O(n)), acceptable for <5K items
  • Data Transfer - Compact JSON responses, minimal payload overhead
  • Caching - No explicit caching; suitable for demo/educational use

Future Scalability

  • Replace JSON with PostgreSQL + ORM (SQLAlchemy)
  • Add Redis caching for frequently filtered queries
  • Implement WebSockets for real-time inventory updates
  • Add pagination for large datasets (>10K items)
  • Deploy with Docker containers
